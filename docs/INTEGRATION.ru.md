# Включение Grain Flow в zynthian-eka

Подготовка к публикации. Публичный репозиторий пока не изменён и push не выполнен.

## Что переносится

Плагин переходит в `plugins/grainflow/`: исходники, LV2-метаданные и их генераторы,
виджет, тесты, Makefile, LICENSE, README на двух языках и docs со скриншотами.
Результаты сборки, тестовые WAV, внутренние настройки и вложенный `.git` не переносятся.

Стабильные имена сохраняются:

| Объект | Значение |
|---|---|
| Название | Eka Grain Flow |
| LV2 URI | `http://dmtry3.github.io/zynthian-eka/grainflow` |
| Бандл | `eka-grainflow.lv2` |
| Бинарник | `eka_grainflow.so` |
| Виджет | `zynthian_widget_eka_grain_flow.py` |
| Пользовательские пресеты | `Eka_Grain_Flow.presets.lv2` |

Имя Python-виджета намеренно содержит `grain_flow`: его ищет Zynthian по названию
плагина. При переносе не переименовывать его в `grainflow`.

## Порядок слияния

1. Зафиксировать готовую версию в приватном репозитории. Проверить, что в коммит
   входят текущие изменения и оба PNG из docs; приватный репозиторий не удалять.
2. В актуальном `zynthian-eka` создать отдельную ветку интеграции. Сначала проверить
   состояние рабочей папки, чтобы не задеть чужие незакоммиченные изменения.
3. Импортировать подготовленный коммит через `git subtree add --prefix=plugins/grainflow`
   с локальным путём приватного репозитория и `--squash`. Это помещает плагин в нужную
   папку одним импортом; полная история разработки остаётся в приватном репозитории.
   Обычный merge двух корней репозиториев здесь не нужен.
4. Применить подготовленные изменения корня из `docs/INTEGRATION.patch`:
   README EN/RU (шестой плагин, описание и скриншот), список общего deploy-скрипта.
   Корневой Makefile уже обнаруживает `plugins/*`, поэтому отдельных целей добавлять не нужно.
   Обновить локальные AGENTS/CLAUDE монорепозитория, если они есть; они исключены его `.gitignore`.
5. Собрать только Grain Flow и выполнить его тесты в новой папке. Проверить общие
   цели `grainflow`, `install-grainflow`, `uninstall-grainflow`, `deploy-grainflow`.
6. На Pi установить из новой папки и перезапустить Zynthian. Проверить Factory,
   виджет, пользовательские пресеты и ранее сохранённый снапшот. Установщик
   перепривяжет существующие ссылки к новой папке, имя плагина останется прежним.
   Данные захваченного аудиобуфера не сохраняются в State и до переноса тоже не сохранялись.
7. Просмотреть diff, затем включить ветку в main и опубликовать только подготовленные
   коммиты. Удаление старой папки разработки и GitHub Release — отдельные действия.

`INTEGRATION.patch` подготовлен относительно локальной версии монорепозитория на
2026-11-16. Перед применением к более новому main сначала выполнить `git apply --check`;
при расхождениях обновить те же разделы вручную, не откатывая чужие изменения.

## После публикации: установка одного плагина

На Zynthian, по SSH под root:

```bash
cd /root/zynthian-eka
git pull
sudo make install-grainflow
systemctl restart zynthian
```

Для передачи из WSL без GitHub после интеграции:

```bash
cd /home/demetry/projects/zynthian-eka
make deploy-grainflow
```

Это общий скрипт монорепозитория. `plugins/grainflow/scripts/deploy-zynthian.sh`
остаётся помощником для отдельной рабочей копии и по умолчанию использует прежнюю
папку `/root/zynthian-eka-grain-flow`; не путать эти два способа.

## Что ещё проверить на устройстве

Пользователь сообщил рабочий CPU 5–6 %, но точная конфигурация замера не зафиксирована.
Не выдавать это за worst-case benchmark. После переноса остаётся проверить установку
из монорепозитория и загрузку старого снапшота; подробные сценарии — в CHECKLIST.md.

## Результаты подготовки (2026-11-16)

- README EN/RU: актуальные четыре страницы ручек, 25 пресетов, возможности и оба скриншота; локальные ссылки проверены.
- `make test`: 161 проверка движка, 136 проверок LV2-обёртки, виджет — без ошибок.
- В пробной структуре `zynthian-eka/plugins/grainflow` выполнен `SAN=1 make test` — тот же результат без ошибок.
- Проверены общие цели Makefile и дополненный список deploy-скрипта; patch применяется к локальному исходному монорепозиторию.
- Установка и удаление в тестовых каталогах: ссылки указывают на новую папку, пользовательский manifest пресетов сохранён, бинарник не удаляется при uninstall.
- Настоящая установка на Pi из монорепозитория, восстановление снапшота после переноса и публикация ещё не выполнены.
